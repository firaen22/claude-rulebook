## Hunt (a) — inner `jobs -pr` / `case` / `SECONDS`

**Expected:** newline-guarded `case` rejects substring pids (2923 vs 29235); a previous killed-but-unreaped job cannot make the current probe look gone; `SECONDS+1` never lets a live probe outrun the outer `DEADLINE=2` killer.

- Substring pids: `\n123\n` is not a substring of `\n12345\n`. [verified: pattern construction]
- Lingering previous job: `_ppid=$!` is overwritten per candidate (`v26.sh:731`). A leftover pid in `_prun` does not satisfy the current pid’s newline-anchored pattern unless it is the **same integer**. Same-integer reuse requires the previous pid to have been reaped; a zombie holds the pid. [verified: kernel pid-reuse rule + source; `[unverified]` bash 3.2.57 `jobs -pr` format with two jobs — expected one pid per line, same as the outer loop]
- `jobs -pr` as a side effect of the **second** candidate’s poll can reap the first killed zombie. Status is discarded; that is the `_pkilled=yes` path. Harmless. [verified: control flow]

**`SECONDS` fire-at-spawn.** `_pend=$(( SECONDS + 1 ))` is set once, before the candidate loop (`v26.sh:653`). bash 3.2 `SECONDS` is `floor(elapsed)`. Fire time after the assignment is **~(0+, 1.0]s**, not the comment’s “~0.05s to ~1.05s”. If the worker subshell inherits a parent `SECONDS` that is already about to tick (parent setup crossed an integer boundary), the first `SECONDS -ge $_pend` is true on the first loop iteration and the just-spawned probe is killed immediately. Event loss. Cheap. [verified: bash `SECONDS` integer semantics; `[unverified]` whether a `( ) &` subshell on 3.2.57 inherits the parent tick vs. resets]

**Does a live probe outrun the outer kill on the deadline path?** Inner loop order is: `jobs -pr` → deadline kill → **then** `/bin/sleep 0.05` (`v26.sh:733-748`). Max overshoot past `_pend` is one sleep (~0.05s). Second candidate after a spent budget is killed on its first iteration, before sleep (`v26.sh:743-746`). Outer `end=$(( SECONDS + 2 ))` fires ~(1.0, 2.0]s after `v26.sh:791`. Inner ~1s + 0.05s + spawn sits inside that with ~1s of margin **on the deadline path**, provided the inner killer is still alive. [verified: loop order + integer `SECONDS`; `[unverified]` wall-clock measurement]

**Nested `$(jobs -pr)` inside `( ) &`:** the outer watchdog’s `$(builtin jobs -pr)` was measured on this bash in the **parent**. The inner loop is one subshell deeper. If `jobs -pr` in that context returned empty against a live probe, the inner loop would take the “gone” branch, `wait "$_ppid"` would block on the hang, the outer killer would SIGKILL `$wid`, and the probe would be the v22 H01 orphan again. ## Hunt (b) — `wait "$_ppid"` on a wedged child

## Hunt (g) — parent signal mid-probe. Bound is false.

**Expected (their honest limit):** terminating signal to the parent KILLs `$wid`, abandons the hung probe, **window ≤ 1s probe budget**, no CPU spin, no caller stdin.

**Actual:**

Parent trap (`v26.sh:218`):

```bash

```

`jobs -pr` in the **parent** lists `$wid` only. The probe is a **grandchild**. SIGKILL is not trappable; the worker’s inner loop does not run after that. Nobody ever sends the probe the `kill -KILL "$_ppid"` that the 1s bound assumes.

| Question | Answer |
|---|---|
| Can the orphan live longer than 1s? | **Yes. Forever**, for any killable (R/S) probe. The 1s timer lives inside `$wid`. [verified: source] |
| Can it spin CPU? | **Yes.** H01 stub is `while :; do :; done` (`contract.py:185`). A real interpreter in a tight init loop is the same class. [verified: stub + no killer] |
| Can it hold caller stdin? | **No** (probe `</dev/null`). Inner `/bin/sleep` can, briefly — M1. [verified: redirections] |

**This is not D-state.** Pid-directed SIGKILL on an R-state hang stub always completes **if someone sends it**. Someone does not.

**Delivery-shape split (config-dependent safety):**

- **Group-directed** TERM/KILL (harness `E_grp_*`, `grpsig.py` I01): probe is in the same pgid (no `set -m`), has SIG_DFL, **dies with the group**. I01 is expected to PASS. [verified: source; `[unverified]` run]

The comments at `v26.sh:700-704` say the window is “at most the shared 1s probe budget … instead of unbounded.” Two readings: (1) orphan lifetime ≤ 1s — **false**; (2) the signal is only dangerous during the ~1s probe phase — true, and then the orphan lifetime is still unbounded. ## Findings (severity-ranked)

### H1 — C3 abandoned spinner; documented 1s bound is false
**Where:** `v26.sh:218` (parent trap) × `v26.sh:700-704` (honest limit) × `v26.sh:730-746` (probe + inner kill).  
**Mechanism:** Parent trap pid-KILLs `$wid`. Probe is not a parent job. Inner `SECONDS` killer dies with the worker. A runnable hang (`contract.py:185`) is reparented to launchd and burns CPU with no deadline.  
**Not D10:** D-state is unkillable; this process is killable and simply never signaled.  
**Config class:** **Safe under group-directed signals** (harness `preexec_fn=setpgid(0,0)` + I01). **Unsafe under PID-directed TERM/INT/… to the hook pid**, which is what `D_pid_*` exercises — just not combined with a hung candidate. If production Claude Code does **not** isolate the hook pgid, group signals would also kill the caller; the hook cannot `kill 0` to clean grandchildren without proving that isolation.  
**Concrete fix:** Inside the worker subshell, install the same `kill -KILL $(builtin jobs -pr)` trap on EXIT/TERM **before** spawning a probe, **and** change the parent trap to `kill -TERM "$wid"` so that trap can run, then `kill -KILL "$wid"` for the D-state worker. Back-to-back TERM+KILL is still a race (no sleep in a trap — round 11). Closing the race without `set -m` and without `kill 0` needs the probe to be a **direct child of the parent** (parent `jobs -pr` would then list it) or a dedicated parent-owned killer pid. Do not document an unenforced 1s lifetime as a substitute.  
**Evidence:** [verified: source]. Reproduction (not run): rewrite H01 stub as now, deliver `SIGTERM` to the hook pid at 0.35s, `ps` for `interp_hang/python3` after parent exit. Expect 1 non-zombie survivor. `[unverified]`

### M1 — inner `/bin/sleep` inherits caller stdin
**Where:** `v26.sh:748` vs worker fd 0 at `v26.sh:760`.  
**Mechanism:** Probe phase intentionally keeps caller stdin on the worker so the later `exec` of `OBS_CODE` can read the event. Foreground `/bin/sleep 0.05` inherits that fd. SIGKILL of `$wid` during sleep orphans a pipe reader. Typical duration 0.05s; unbounded if `/bin/sleep` wedges.  
**Fix:** `/bin/sleep 0.05 </dev/null >/dev/null 2>/dev/null || builtin true`, or stash stdin on fd 4 for the duration of the probe loop and restore it only on the exec path.  
**Evidence:** [verified: source]. `[unverified]` whether a 0.05s orphan actually stalls a Claude Code stdin writer (pipe buffer usually absorbs a few KB).

### L1 — integer `SECONDS+1` can fire at first spawn
**Where:** `v26.sh:647-653, 743-746`.  
**Mechanism:** Comment’s “~0.05–1.05s” is wrong; fire is the next integer tick. Cheap event loss, including “working interpreter killed, second candidate also killed, exit 18”.  
**Fix:** if a tighter bound is required, poll a non-integer clock (not available in bash 3.2 without a fork). Otherwise correct the comment and accept load-dependent loss.  
**Evidence:** [verified: `SECONDS` semantics]. `[unverified]` hit rate on this host.

### L2 — H02 fixture still only stubs candidate 1; H02 note still says “1337”
**Where:** `contract.py:142, 196`.  
**Not a hook bug.** Does not make v26 look better than it is on the “all interpreters dead” path.  
**Fix:** rewrite both paths, or point the second at another fail stub.
